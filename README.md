# Mac Clean

Mac Clean 是一个原生 macOS 清理工具，帮助用户查找可清理内容、识别重复文件并卸载应用。项目使用 Swift 6、SwiftUI 和 Foundation 构建，最低支持 macOS 13。

## 功能

- 智能清理缓存、日志、浏览器数据、废纸篓和已卸载应用残留，并按类型汇总展示。
- 查找重复文件，默认只处理不小于 1 MiB 的文件。
- 支持手动添加、移除和持久化重复文件扫描目录。
- 自动排除系统元数据、应用自身缓存、依赖包和常见开发工具缓存，减少无意义结果。
- 重复文件不会自动勾选，所有待删除文件都由用户逐项选择并确认。
- 支持在 Finder 中打开文件所在目录，便于删除前核对文件。
- 支持从应用列表查看应用信息并执行卸载。

## 设计边界

Mac Clean 的目标是帮助用户找到可解释、可核对的清理候选，而不是无差别删除文件。扫描结果会展示路径、大小、来源和风险；无法确认安全性的对象只展示，不会自动加入删除集合。

应用卸载会根据应用名称、Bundle ID 和关联路径生成候选项，避免把其他应用的数据误关联。浏览器个人资料、Cookie、密码库、聊天记录、用户文档、共享容器和开发凭据不属于默认清理对象。

智能清理默认不勾选任何文件。Cookie 类别只列出指定位置的 `.binarycookies` 文件，Web 缓存只识别明确的缓存目录。网站持久化存储、登录数据库、应用运行依赖和 Mac Clean 删除审计日志均受保护。开发构建产物只检查 Xcode 的 `DerivedData`，跳过包依赖和历史构建日志。

首次扫描会枚举本机第三方应用的偏好文件，并从 `Application Support`、`HTTPStorages`、`WebKit` 和保存状态目录寻找独立的应用标识证据。目录使用产品短名时，要求它在偏好标识中唯一且有对应的产品目录或完整标识证据。扫描器还会核查已安装副本、运行中的应用、命令行入口及相关后台服务。

通用规则可识别私有日志、临时缓存、符合 Chromium 结构的缓存文件，以及主目录中能确认归属的 `.<产品名>/logs` 日志。结果按应用标识合并。清理前会重新读取归属证据并核对文件身份。已知产品的特殊目录继续适用已有规则。

WorkBuddy 的 `~/.workbuddy/logs`、`~/.workbuddy-ai/logs` 和 CC Switch 的 `~/.cc-switch/logs` 也纳入智能清理。符合残留条件的 `.log` 普通文件按应用分组展示，可展开逐项勾选后移入废纸篓。

应用名称映射维护在 `Sources/MacCleanCore/Resources/ApplicationNameMappings.json`，按 Bundle ID 映射实际应用名称，并兼容缓存目录中常见的应用目录名。数据以公开的 macOS 应用包标识和各应用公开仓库中的 `Info.plist` 为主要核对来源，新增或更正应用时直接更新该 JSON，构建脚本会将资源包一并放入应用包。

废纸篓需要读取用户目录下的 `~/.Trash`。如果 macOS 拒绝访问，智能清理会保留废纸篓类型并提示用户在系统设置的“隐私与安全性 → 完全磁盘访问权限”中允许 Mac Clean。

## 安全行为

疑似残留须逐文件勾选，执行前再次核对归属、安装状态和文件身份，随后移入系统废纸篓，可在清空前恢复。其余清理操作为永久删除。应用卸载可能预选部分项目，请先核对勾选清单。智能清理和重复文件默认全部未勾选。

重复文件扫描目录会保存到用户配置中，更新应用配置或重新启动应用后仍会保留。已选择的目录可在扫描界面直接移除。

删除前会检查目标是否存在、是否位于允许范围内，以及目标本身是否为符号链接。删除结果会尝试写入本机的 `~/Library/Logs/MacClean/operations.ndjson`，日志包含完整文件路径，分享前请检查其中的个人信息。

## 重复文件扫描

- 扫描当前列表中的目录。首次使用时会列出下载、文稿等常用目录，用户可增删。默认文件大小下限为 1 MiB，且没有文件数量上限。
- 自动跳过符号链接、应用包内部内容、macOS 元数据和常见缓存或依赖目录，例如 `node_modules`、`vendor`、`.pnpm`、`.npm`、Pods、Carthage、`.gradle`、`.m2` 和 Python 缓存。
- 先按文件大小分组，再读取文件头尾各 32 KiB 的片段；片段相同后才计算完整 SHA-256，减少无意义的磁盘读取。
- 最多使用 3 个后台工作线程，并支持取消扫描、显示进度、记录跳过路径和统计实际读取量。
- 重复组和文件列表采用分批加载，每次显示 50 项，避免大目录一次性创建过多界面元素。
- 重复文件全部由用户手动选择，不提供“保留副本”或自动判断；文件名旁可在 Finder 中定位原文件。

## 技术结构

项目使用 Swift 6、SwiftUI 和 Foundation，最低支持 macOS 13，并将核心逻辑放在独立的 `MacCleanCore` Swift Package 中：

```text
SwiftUI 应用
  ├─ 扫描进度、结果展示和手动选择
  ├─ 类型汇总、应用分组和删除状态
  └─ 应用卸载界面
        ↓
MacCleanCore
  ├─ 扫描器与规则匹配
  ├─ 应用关联和风险分级
  ├─ 重复文件分层哈希
  ├─ 路径保护和永久删除
  └─ 扫描目录持久化
```

核心逻辑使用自动化测试覆盖规则匹配、应用关联、目录持久化、重复文件识别、分层哈希、取消扫描、选择状态和删除保护。

## 构建与安装

```bash
# 运行测试
swift test --jobs 1

# 仅构建，应用包输出至隐藏目录 .build/app/MacClean.app
bash Scripts/build_app.sh

# 构建并安装到 ~/Applications/MacClean.app，已打开时自动退出并重启
bash Scripts/publish_app.sh
```

构建脚本使用 `Resources/Info.plist` 中的应用元数据，生成 `.build/app/MacClean.app`。安装脚本将其复制到 `~/Applications`，并向系统注册安装版，避免聚焦搜索同时收录开发副本。

## 项目结构

```text
Sources/MacCleanApp/       SwiftUI 应用界面
Sources/MacCleanCore/      扫描、规则、重复文件和删除逻辑
Tests/MacCleanCoreTests/   核心逻辑测试
Resources/                 应用元数据和图标资源
Scripts/                   构建、发布和图标生成脚本
```

图标资源的生成与打包说明见 [Resources/README.md](Resources/README.md)。
